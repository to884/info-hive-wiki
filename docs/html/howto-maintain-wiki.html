wiki の保守コマンドを使い分ける

すでに作ってある wiki が対象です。複数の wiki を使っている場合は、対象の wiki のパスをコマンドと一緒に伝えます。

既存の wiki を新しい版に合わせる

wiki プラグインを更新したあと、既存の wiki で作業を再開する前に /wiki:upgrade を実行します。 古い wiki に graph/ontology.yaml がなく、グラフを使い始めたいときにも実行します。

  1. Claude Code では /wiki:upgrade、Codex では $wiki:info-hive upgrade を送ります。ユーザー wiki が対象なら末尾に --user を付けます。
  2. graph/ontology.yaml などのひな形やフォルダーを追加した場合は、出力の「作成した」に表示されます。 すでにあったものは「すでにあったので飛ばした」に表示されます。 コマンドは原本の保管先を .wiki-cache/raw-roots.d/ に記録し、CLI 検索用の .wiki-cache/search-index.json と .wiki-cache/embeddings.sqlite を同期します。 実行環境の出力が "status": "ready" なら、規約の確認へ進みます。 セットアップに失敗した場合は、出力のエラーを確認し、原因を解消してから同じコマンドを実行します。
  3. SCHEMA.md に不足している節が提示されたら、既存の規約と読み比べます。追加する節を承認し、SCHEMA.md への追記を確認します。

対象の指定や規約の確認は、wiki をアップグレードする手順を参照してください。 グラフを作る必要がある場合は、記事の変更をグラフに反映する手順に進みます。

リンクや記事の内容を点検する

資料を何件か取り込んだあとや、記事をまとめて移動・改名したあとに /wiki:lint を実行します。 型付きの関係（graph.relationships）やオントロジー（graph/ontology.yaml）を編集したあとにも実行します。 継続して資料を取り込む wiki では、週に 1 回など、まとめて指摘を確認できる間隔で実行します。

  1. Claude Code では /wiki:lint、Codex では $wiki:info-hive lint を送ります。
  2. リンク切れや孤立ページなどの指摘と、記事の内容に関する修正案を確認します。オントロジーがある場合は、型付きの関係の指摘も確認します。
  3. 必要な修正を承認します。承認した修正を適用すると、該当する Markdown の記事と、必要に応じて index.md や indexes/ の索引が更新されます。 修正後の結果は log.md に追記されます。同じコマンドで指摘が解消したかを確認します。

記事の変更をグラフに反映する

手元の Markdown を直接使う wiki に graph/ontology.yaml があれば、初めてグラフを作るときに /wiki:graph extract を実行します。 記事の追加・削除・改名・編集やオントロジーの変更をまだグラフに反映していないときは、関係を調べる前に実行します。 プラグインで資料を取り込み、その手順でグラフの更新も済んでいれば、そのまま関係を調べられます。

公開版を使う wiki では、公開用の保存手順で記事とグラフを一緒に更新します。

  1. 型付きの関係やオントロジーを編集した場合は、先に /wiki:lint で点検し、グラフの指摘を確認します。
  2. Claude Code では /wiki:graph extract、Codex では $wiki:info-hive graph extract を送ります。
  3. 抽出したノードとエッジの件数と出力先を確かめます。コマンドは、記事内の wikilink、出典、型付きの関係などを読み取り、 graph/ に graph.sqlite、nodes.jsonl、edges.jsonl、graph.graphml を作成または更新します。

graph/ontology.yaml がない wiki でグラフを使い始める場合は、先に /wiki:upgrade でひな形を追加します。
