info-hive

AI エージェントが、日本語の PDF、Web 記事、文字起こし、メモを Markdown の wiki に整理します。あとから質問すると、wiki の内容をもとに、出典つきで答えます。得られた知識は、次の作業でも使えるように保存できます。

Claude Code と Codex では wiki@info-hive プラグインとして、ほかの対応エージェントでは info-hive スキルとして使います。スキルは Agent Skills 形式です。

インストール

Windows 11 の Claude デスクトップアプリで、Code タブから wiki を入れます。

  1. Claude と、Git・uv・Python 3.12・Visual C++ ランタイムを用意します。
  2. Code タブで info-hive のマーケットプレイスを追加します。
  3. ディレクトリの Wiki を追加し、/wiki:help で導入を確かめます。

Windows 11 の導入手順は、VM で確認した構成と操作をもとにしています。

Codex や Claude Code の CLI を使う場合は、エージェント別の導入方法を参照できます。

WSL 版の Claude Code や Codex でプロジェクト wiki を使う場合は、Windows 側に導入済みでも WSL 側に wiki@info-hive をインストールします。WSL での導入手順

クイックスタート

プロジェクトをまたいで使える wiki を作ります。まず init を実行し、保存先を確認して初期化します。最初の資料を ~/info-hive/raw/your-source.pdf に置いたら、ingest で取り込み、query で質問します。例のパスと質問は、使いたい資料と質問に置き換えてください。

Claude Code

/wiki:init --user
/wiki:ingest ~/info-hive/raw/your-source.pdf
/wiki:query この資料の要点は？

Codex

$wiki:info-hive init --user
$wiki:info-hive ingest ~/info-hive/raw/your-source.pdf
$wiki:info-hive query この資料の要点は？

プロジェクト専用の wiki を作る場合は、init の --user を外します。既定では、そのプロジェクトの wiki/ と raw/ を使います。プラグインやスキルを入れる範囲と、wiki の保存範囲は別々に選べます。

定期的な点検には、Claude Code では /wiki:lint、Codex では $wiki:info-hive lint を使います。検出した問題は修正案として示し、黙って wiki を書き換えることはありません。

できること

  • 資料を要約し、関連するページ、リンク、インデックスを更新します。
  • 日本語の語彙検索と意味検索を組み合わせ、出典つきで質問に答えます。
  • リンク切れ、孤立ページ、frontmatter の欠落、大きすぎるページを点検します。
  • ページ間の関係をグラフで調べ、wiki をブラウザーで閲覧します。
  • /wiki:overview <ページ> で、図を中心にした概要を本文と別に保存し、/wiki:browse で表示します。元のページが更新されると、警告を表示して概要を折りたたみます。
  • 検証済みのタスクの経験を記録し、スキルの変更を提案・評価します。

wiki の正本は手元の Markdown です。同じ wiki を複数のエージェントで使えます。検索の埋め込みと索引もローカルで処理し、外部のベクトルデータベースや埋め込み API は使いません。

Claude Code では、任意の rag@info-hive を有効にすると、PDF の抽出・OCR・索引化を永続ジョブとして処理できます。queued は、依頼を受け付けた段階です。この時点では、PDF の索引化は完了していません。rag がなくても PDF は取り込めます。rag の Codex 対応は含みません。

Claude Code と Codex では、ingest session で実行中の会話を取り込めます。Codex の呼び出し方は $wiki:info-hive ingest session、指定した会話を取り込む場合は $wiki:info-hive ingest session:<ID> です。保存する範囲と伏せ字を確認してから、会話を wiki に取り込みます。

スキルの改善は任意のワークフローです。移植元の調査では品質の向上は示されていません。仕組みと検証の限界で、調査結果の詳細を確認できます。

ドキュメント

HTML マニュアルは、ローカル HTTP サーバー経由で開きます。 手元で docs/html/ を含むフォルダーに移動し、次のコマンドを実行してください。

cd docs/html
python -m http.server 8000 --bind 127.0.0.1

サーバーを起動したまま、ブラウザーのアドレス欄に http://127.0.0.1:8000/ と入力すると、図解と目次を表示できます。 8000 は例です。別の空いているポートを使う場合は、コマンドと URL の両方に同じ番号を指定してください。 読み終えたら、サーバーを起動したターミナルで Ctrl+C を押して停止します。

移植元とクレジット

Praney Behl の llm-wiki-plugin v4.0.1（コミット 2d24ccf、MIT ライセンス）を日本語向けに移植しました。起点と取り込んだ修正は UPSTREAM.md に記録しています。移植元のホスト型 wiki は含めていません。

LLM Wiki のパターンは Andrej Karpathy の llm-wiki gist にもとづきます。移植元の検索は Cerebras の How We Built Our Knowledge Base を参考にし、ローカル検索への移行時には Basic Memory と比較しています。スキルの改善のワークフローは WikiSkill を応用しています。
