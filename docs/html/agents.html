エージェント

info-hive は agentskills.io 形式のスキルです。下の表にあるエージェントで使えます。スキルで使える操作は、wiki と実行環境の初期化、ハイブリッド検索または語彙検索、構造の点検（lint）、統計、グラフの点検・抽出・問い合わせです。依存パッケージが必要なスクリプトは、uv run --script で実行します。パッケージのバージョンは PEP 723 の形式で固定しています。

Claude Code claude-code /wiki:* スラッシュコマンド（同梱）または自然言語 ✅
Codex (OpenAI) codex（スキルだけの場合） プラグインは $wiki:info-hive、スキルだけなら $info-hive / 自然言語 ✅

OpenCode は .claude/skills/ と ~/.claude/skills/ も読むので、Claude Code 向けにインストールしてあれば、改めてインストールしなくても使えます。

LLM モデルと用途

資料の要約、関連する wiki ページの更新、質問への回答は、Claude Code や Codex などで現在選んでいる会話モデルが担当します。 操作によっては、一部の作業を別のモデルに任せたり、用途に合う設定を利用者に案内したりします。

操作 モデルと設定 モデルが担当する作業
Web ページの取り込み Claude Code では wiki:web-raw の既定値 sonnet（Claude Sonnet）。Codex や、このエージェントを使えない環境では現在の会話モデル 取得した本文を必要に応じて日本語に訳し、画像の説明を加えて原資料（raw）を作ります。検査後の要約と wiki の更新は、取り込みを始めた会話モデルが担当します。
Claude Code のフックが見つけた候補ページの読み取り R0 は現在の会話モデル。R1・R2 は wiki:wiki-reader が sonnet と推論エフォート low を使用。R3 は同じモデルで medium 候補が 1 件のときや委任が無効なときは会話モデルが読みます。複数の候補から根拠を拾うときは読み取り専用のエージェントに任せます。ページ間の比較、矛盾の確認、設計判断の根拠が必要なときは、会話モデルが理由を示して R3 を選べます。
YouTube 字幕の取り込み Claude Code では Claude Opus 5.5（medium）、Codex では GPT-6.2 Sol（high）を推奨 スクリプトが保存した字幕を読み、要約を書きます。自動字幕に聞き違いがあれば、訂正案や不確かな点を要約に記します。推奨設定への切り替えは利用者がホスト側で行います。
/wiki:evolve によるスキルの評価と改善 利用者が評価設定で役割ごとにモデル ID を指定 タスクの実行、経験の整理、変更案の作成、回答の採点を分担します。評価の設定と実行手順

表の sonnet は Claude Code のモデル指定名です。候補ページの読み取りでエフォートを選ぶ際に評価したモデルは Claude Sonnet 5.5（claude-sonnet-5-5）です。

任意の判定レイヤーを有効にすると、専用モデルが検索結果の関連度やグラフの関係を裏づける証拠の有無などを判定します。 既定では無効です。ローカルで使う場合のモデルは Liquid d1-2B です。判定モデルとバックエンドの一覧

意味検索に使う埋め込みモデル

埋め込みモデルは、質問と本文をそれぞれ数値の列（ベクトル）に変換します。意味検索では、質問のベクトルに近い本文を探すため、質問と資料で使われている言葉が違っても、関連する箇所を見つけられます。回答を書くのは、その箇所を読んだ会話モデルです。

何をどこで検索するか 埋め込みモデル 設定できること
wiki ページを wiki の MCP サーバーで検索 cl-nagoya/ruri-v3-130m（512 次元） サーバーが使うモデルは固定です。質問には 検索クエリ: 、本文には 検索文書: を自動で付けて埋め込みます。
wiki ページを CLI の wiki_search.py で検索 既定は intfloat/multilingual-e5-small（384 次元）。intfloat/multilingual-e5-large（1,024 次元）も選べます。 環境変数 INFO_HIVE_EMBED_MODEL にモデル名を指定します。変更すると次の検索で CLI 用の索引を作り直します。--no-embed を付けると語彙検索（BM25）だけを使います。
PDF の本文を Claude Code の rag@info-hive で検索 既定は cl-nagoya/ruri-v3-130m（512 次元）。同じ Ruri v3 系列の 30m（256 次元）、70m（384 次元）、310m（768 次元）も選べます。 /rag:setup で embedding_model を指定します。たとえば CPU の負荷を抑えたい場合は cl-nagoya/ruri-v3-30m を選べます。

rag で埋め込みモデルを変更したら、/rag:status の reingest に載った PDF を取り込み直します。モデルだけを変えた場合は、保存済みの本文と OCR 結果を再利用し、ベクトルと索引を作り直します。 wiki の CLI で使う E5 の容量と検索精度は、埋め込みモデルを切り替えるで比較できます。

事前準備

エージェントがコマンドを実行する環境に、Git と uv、Python 3.12 以上を用意します。初期化は python を直接呼び出すので、次のコマンドで確認します。

git --version
uv --version
python --version

uv 経由の同梱スクリプトには Python 3.12〜3.14 を使います。この範囲の Python が見つからなければ、uv が取得します。依存パッケージも uv が用意します。

Windows で Claude デスクトップアプリの Code タブを使う場合は、HTML マニュアルの開き方を参照してください。 マニュアルの目次から「Code タブに wiki を入れる」を開くと、導入手順を確認できます。

インストールのコマンド例

WSL でプロジェクト wiki を使う

WSL 版の Claude Code や Codex でプロジェクト wiki を使う場合は、Windows 側に導入済みでも WSL 側に wiki@info-hive をインストールします。 既定では Windows 版と WSL 版の CLI は別々の設定を使うため、リポジトリをどちらに置いていても、CLI を動かす環境にインストールします。

WSL のターミナルで command -v claude または command -v codex を実行し、使う CLI が WSL 側にインストールしたものを指すことを確認します。 パスが表示されないか、/mnt/c/ などにある Windows 版を指す場合は、WSL 側に Linux 版の CLI を用意し、その CLI を使います。

WSL 側で対象リポジトリのルートに移動し、事前準備 を済ませます。 python3 だけが使える環境では、Python 3.12 以上を python でも起動できるようにします。 同じ環境で Claude Code CLI または Codex CLI の手順に従ってプラグインを入れます。 導入後は、Claude Code なら /wiki:help、Codex なら $wiki:info-hive help で操作の一覧が表示されることを確認します。

WSL の閲覧 URL を Windows で開く

WSL 2 の NAT モードでは、Windows 側からの接続に localhostForwarding を使います。 WSL 内で wslinfo --networking-mode を実行できる環境では、動作中のモードを確認できます。 Windows の %USERPROFILE%\.wslconfig の [wsl2] に localhostForwarding=false があれば、true に変更します。 指定がないときの既定値は true です。次は NAT モードで設定を明示する例です。

[wsl2]
networkingMode=nat
localhostForwarding=true

設定を変えた場合は、すべての WSL ディストリビューションで作業を保存し、Windows の PowerShell で wsl --shutdown を実行します。 wsl --list --running に稼働中のディストリビューションが表示されなくなってから、WSL を起動し直します。 WSL を起動し直したら、Claude Code で /wiki:browse または Codex で $wiki:info-hive browse を実行します。 閲覧サーバーはホストとポートを照合するので、表示された http://127.0.0.1:… の URL をそのまま Windows 側のブラウザで開きます。 Windows 側で開けない場合は、WSL 内にブラウザがあれば、同じ URL を開いて閲覧サーバーが動いていることを確認します。

wsl --version が 3.0.5.0 の環境で、Ubuntu 24.04 から起動した閲覧ページを Windows 版 Edge で表示できることを確認しました。 mirrored モードでは localhostForwarding は使われません。その構成で閲覧できる場合は、そのまま使えます。Microsoft Learn の WSL 設定

Claude Code CLI

Claude Code には、スキル、MCP サーバー、スラッシュコマンドが入ります。マーケットプレイスは to884/info-hive-marketplace にあります。

/plugin marketplace add to884/info-hive-marketplace
/plugin install wiki@info-hive

プラグインを HTTPS で取得する

Claude Code が SSH で GitHub に接続できない場合は、環境変数 CLAUDE_CODE_PLUGIN_PREFER_HTTPS を 1 に設定して起動します。公開リポジトリを HTTPS で取得する場合、GitHub の認証情報は不要です。

PowerShell では次を実行します。

$env:CLAUDE_CODE_PLUGIN_PREFER_HTTPS = '1'
claude

macOS・Linux のターミナルでは次を実行します。

CLAUDE_CODE_PLUGIN_PREFER_HTTPS=1 claude

起動した Claude Code のチャットで、マーケットプレイスの追加とプラグインのインストールを実行します。マーケットプレイスがすでに追加されていれば、プラグインのインストールから再試行できます。

Codex CLI

事前準備を済ませ、Codex CLI が使えるターミナルで次を実行します。スキルと MCP サーバーをまとめて導入できます（Codex CLI 0.166.0 で確認）。

codex plugin marketplace add to884/info-hive-marketplace
codex plugin add wiki@info-hive

導入後は新しい Codex のチャットで $wiki:info-hive init、$wiki:info-hive ingest <ソース>、$wiki:info-hive query <質問> の形で使います。$wiki:info-hive help で操作の一覧を表示し、$wiki:info-hive help query で個別のヘルプを表示します。MCP は自動登録されます。初回の依存とモデルの取得には数分かかることがあります。社内ネットワークの証明書の設定は MCP サーバーを参照してください。

Claude Code の /wiki:* は Codex のスラッシュコマンドにはなりません。Web の raw は Codex 自身が作り、Claude CLI は不要です。$wiki:info-hive ingest session で実行中の Codex の会話を、$wiki:info-hive ingest session:<ID> で指定した会話を取り込めます。従来の JSONL とデータベースの履歴の両方を、Codex の読み取り API で取得します。取り込みを依頼したターンを除外し、伏せ字と保存前の確認を行います。rag の Codex 対応は含みません。

開発用の info-hive-dev のチェックアウトを試すときは、親リポジトリのルートで次を実行します。ローカルのカタログは、チェックアウトした info-hive-wiki を指します。

codex plugin marketplace add .
codex plugin add wiki@info-hive-dev

Codex のスキル単体とその他のエージェント

Codex のスキルだけを使う場合、および Cursor、Gemini CLI、OpenCode、OpenClaw、Pi では、Node.js と skills CLI を使ってスキルをインストールします。対応表の --agent の値に置き換えて使います。スキルだけの場合は、MCP の自動登録とプラグインの commands/ は含まれません。同梱の CLI とリファレンスを使い、Codex の呼び出し名は $info-hive になります。

npx skills add to884/info-hive-wiki -a codex -g
npx skills add to884/info-hive-wiki -a cursor -g
npx skills add to884/info-hive-wiki -a gemini-cli -g
npx skills add to884/info-hive-wiki -a opencode -g
npx skills add to884/info-hive-wiki -a openclaw -g
npx skills add to884/info-hive-wiki -a pi -g

現在のプロジェクトだけにインストールするには、-g を外します。

OMP ("Oh My Pi") と Hermes Agent は、まだ npx skills のレジストリに載っていません。リポジトリをクローンし、エージェントのスキル用ディレクトリにスキルへのシンボリックリンクを張ります。OMP は、管理対象のスキルとユーザーのスキルを ~/.omp/agent/skills/ から読み込み、skill:// で公開します。

git clone https://github.com/to884/info-hive-wiki.git
mkdir -p ~/.omp/agent/skills ~/.hermes/skills
ln -s "$(pwd)/info-hive-wiki/skills/info-hive" ~/.omp/agent/skills/info-hive
ln -s "$(pwd)/info-hive-wiki/skills/info-hive" ~/.hermes/skills/info-hive

エージェントのメモリファイル

wiki を作ったら、エージェントがその場所を覚えておけるように、短い記述を追加します。プロジェクトをまたいで使うユーザースコープの wiki なら、~/info-hive/wiki/ のようなユーザーレベルの固定パスをエージェントのグローバルな指示に書きます。プロジェクト専用の wiki なら、相対パスをプロジェクトのメモリファイルに書きます。ファイル名はエージェントによって違います。

エージェント メモリファイル
Claude Code CLAUDE.md
Codex (OpenAI) AGENTS.md
Cursor AGENTS.md（または .cursor/rules/*.mdc）
OpenCode AGENTS.md（CLAUDE.md も読む）
Gemini CLI GEMINI.md
Pi Agent AGENTS.md
OpenClaw AGENTS.md
OMP (Oh My Pi) AGENTS.md

複数のエージェントを使う場合は、対応しているエージェントでは AGENTS.md を正本にし、CLAUDE.md はそのシンボリックリンクにできます。スキルが、ユーザーの承認なしにメモリファイルに書き込むことはありません。ユーザースコープ用とプロジェクト用の記述の例は、skills/info-hive/references/agent-memory-integration.md にあります。

スラッシュコマンドは Claude Code 専用です。ほかのエージェントでは、「この論文を wiki に追加して」「X について wiki には何と書いてある？」「wiki に lint をかけて」のように、自然言語でスキルを呼び出します。wiki そのものは特定のエージェントに依存しないので、あるエージェントで取り込み、別のエージェントでクエリすることもできます。

経験の記録と手順の改善

一覧にあるスキル対応のエージェントはどれも、インストールされた references/evolution-workflow.md と scripts/wiki_evolve.py を使い、自然言語で /wiki:learn と /wiki:evolve のワークフローを実行できます。スラッシュコマンドそのものがあるのは Claude Code だけです。記録とライフサイクル管理のツールは、Python の標準ライブラリだけを使います。共通の評価用アダプターは、9つのホストすべてに対応しています。ただし、ホストごとに、インストールされているバージョン、認証、使えるツール、報告される使用量の集計が異なります。教訓を記録するために、新しくエージェントとの連携を作る必要はありません。経験の記録とスキルの改善で、実行要件と実地検証の結果を確認できます。
