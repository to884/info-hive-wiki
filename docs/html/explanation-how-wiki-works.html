原本と wiki のページ

長期の調査、会議で決めたこと、繰り返し尋ねられる質問など、別のセッションでも使う知識を wiki に残せます。同じフォルダーを使う複数のエージェントでページを読み継げます。

原本は raw/ に置きます。要約や関係するページは wiki/ に置き、どの資料を根拠にしたかを記します。要約を見直すときは、原本までたどれます。

フォルダーの CLAUDE.md に wiki の場所が書いてあれば、新しい Code セッションからもその場所を探せます。

索引と検索の役割

質問を受けると、エージェントは索引とページを読みます。索引で候補が見つからないときは、検索で候補を探します。

RAG は質問に合わせて資料を検索し、見つかった箇所を回答に使います。info-hive の wiki は取り込みの時点で要約や資料同士の関係をページに書き、次の質問でも使えるようにします。

初期化では e5 を取得します。MCP が初めて意味検索用の索引を作るときは、wiki が ruri を取得します。取得している間は語彙検索の結果を返すことがあります。

点検で確かめること

構造の点検ではリンク切れや孤立ページを確認します。内容の点検では、古い記述、文書間の矛盾、原本で裏づけられる範囲を確認します。修正案を承認すると、該当するページを更新できます。

rag との関係

rag プラグインは PDF の抽出と索引化を受け持ちます。wiki は抽出した資料を参照し、要約とページのつながりを残します。
