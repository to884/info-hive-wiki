`info-hive` スキルのクエリワークフローに従い、wiki をもとに次の質問に答える。

質問: $ARGUMENTS

スキルに書かれているクエリの手順をすべて実行する。

0. `<WIKI_ROOT>` は、ユーザーが明示したパス、もっとも近いプロジェクトの指示、グローバルなエージェントの指示の順に探し、どれにもなければ作業領域の設定（`.info-hive/workspace.json`）の `dirs.wiki`、それもなければ現在のプロジェクトの `wiki/` とする。指示が別の wiki を指定しているときに `${PWD}/wiki` を前提にしてはならず、2つの wiki を黙って混ぜてもならない。
1. `<WIKI_ROOT>/SCHEMA.md` がなければ、初期化された wiki ではない（ほかの用途の `wiki/` のこともある）。MCP のツールもスクリプトも呼ばず、何も書かずに止まり、ユーザースコープの wiki なら `/wiki:init --user`、プロジェクトの wiki なら `/wiki:init` を提案する。別の場所の wiki に黙って切り替えたり、`SCHEMA.md` を自分で作ったりしてはならない。ツールやスクリプトが「初期化された wiki ではない」と返したときも同じにする。あれば、このセッションでまだ読んでいなければ、最初に `<WIKI_ROOT>/SCHEMA.md` を読む。
2. `<WIKI_ROOT>/index.md`（インデックスが分割されている場合は、該当する `<WIKI_ROOT>/indexes/<type>.md`）を読み、候補のページを見つける。
3. 候補のページを読む。`[[wikilinks]]` は必要なものだけをたどり、すべてのリンクを再帰的に追いかけない。
4. 質問の答えは、自分の知識ではなく wiki から取る。答えを知っていると思う質問でも、wiki に書かれていることを確かめてから答える。インデックスから適切な候補が見つからない場合は、wiki に関係する内容がないと伝える前に、ローカルのハイブリッド検索を実行する。API キーを調べたり、求めたりしてはならない。検索は端末の中で行い、wiki やクエリのテキストを外に送らない。MCP のツールと CLI の使い分けは、`info-hive` スキルの「MCP のツールと CLI の使い分け」に従う。
4a. wiki の MCP サーバーのツール `query` が使える場合は、`wiki=<WIKI_ROOT の絶対パス>`、`query=<検索語>`、`top=10` を渡す（ツール名は接続に表示されたもの。Claude Code では `mcp__plugin_wiki_wiki__query`）。日本語の検索語は、分かち書きせずにそのまま渡す（「軽減税率の対象」）。語彙検索は日本語を2文字ずつ区切って照合するので、助詞を除いたり語を空白で区切ったりしなくてよい。必要に応じて `type="concept"`、`tags=["<tag>"]`、`since="YYYY-MM-DD"` で絞り込み、1 ページから返すセクションの数は `per_page` で変える。結果の形は CLI の `--json` と同じである。ツールが結果を返したら、0 件でも、同じ検索語で CLI からやり直さない。サーバーの語彙検索はすでに wiki 全体を対象にしているので、やり直しても新しい情報はほとんど得られない。検索語を変えて探し直すのはよいが、2 回までにする。それでも候補が見つからなければ、手順 7 に進む。結果に `warning` があるとき（埋め込みモデルを用意している途中、使えない、索引を埋め込んでいる途中）も、語彙検索はすでに wiki 全体を対象にしているので、その結果を使い、意味の検索を使えなかったか一部だけだったことを回答に添える。確からしさの上限と上げる方法は、手順 6b に従う。
4b. ツールが使えない、呼び出しが返らない、またはページ単位の順位（`--granularity page`）か依存パッケージを使わない決定的な検索が要る場合は、CLI を使う。`uv run --script "${CLAUDE_PLUGIN_ROOT}/skills/info-hive/scripts/wiki_search.py" "<検索語>" --wiki "<WIKI_ROOT>" --top 10 --cache --json` を実行する。バックエンドは FastEmbed と sqlite-vec で、依存パッケージが動かない場合は自動的に語彙ベースの BM25 の結果を返す。依存パッケージを使わない、決定的な語彙ベースの検索にしたい場合は、代わりに `python "${CLAUDE_PLUGIN_ROOT}/skills/info-hive/scripts/wiki_search.py" "<検索語>" --wiki "<WIKI_ROOT>" --top 10 --cache --json --no-embed` を実行する。`uv run --script` の形に `--no-embed` を付けても、uv は宣言されたセマンティック検索用のパッケージを解決してしまうので、付けてはならない。必要に応じて `--type concept` や `--tag <tag>` を使い、ページ単位で順位を付けたいときは `--granularity page` を使う。ツールが使えずに CLI に戻ったときは、そのことをユーザーに伝える。
5. 「X にリンクしているページは？」という質問には、grep ではなく `python "${CLAUDE_PLUGIN_ROOT}/skills/info-hive/scripts/wiki_search.py" "" --wiki "<WIKI_ROOT>" --backlinks <slug>` を使う。MCP のツールにはこの機能がない。
5b. 関係を問う質問（「X とつながっているものは？」「Y を提案したのは誰？」「A から B への経路をたどって」）で、`<WIKI_ROOT>/graph/graph.sqlite` がある場合は、ページを読む前にグラフに問い合わせ、構造化された隣接ノードを得る。MCP のツール `graph` が使える場合は、`wiki=<WIKI_ROOT の絶対パス>` と `command="neighbors"`、`node=<id>` を渡す（`facts` は `about`、`edges` は `subject`、`path` は `from_node` と `to_node`）。使えない場合は `python "${CLAUDE_PLUGIN_ROOT}/skills/info-hive/scripts/wiki_graph_query.py" "<WIKI_ROOT>" neighbors --node <id>`（または `facts`、`edges`、`path`）を実行する。開く wiki ページは、型付きエッジの結果をもとに選ぶ。重要な主張については、グラフの行だけをもとに答えてはならない。
6. 使った wiki ページへの `[[wikilink]]` を出典として付け、回答をまとめる。矛盾がある場合は、どちらか一方を選ばず、矛盾をそのまま示す。
6b. 回答の終わりに、確からしさ（confidence）を「高」「中」「低」で示し、理由を添える。決め方と書き方は、スキルのクエリワークフローの「手順 5b」に従う。結論と、結論を導いた前提を判定する。前提は書かれていた場所（ソースの要約ページか raw で確かめたか、シンセシスのページにしかないか、など）で出発点を決め、結論は導き方（そのまま述べたか、決まった手順で導いたか、判断を加えたか）で決める。それぞれに上限（仮説、矛盾、置き換えられた記述、時期の不明、検索の縮退など）を当て、もっとも低いものに合わせる。シンセシスのページは根拠に数えない。数値の確率にしてはならない。「中」か「低」のときは、確からしさを決めた要因ごとに、上げる方法（取り込むとよい資料、確かめるページ、使うコマンド）をユーザーに提案する。wiki を書き換える方法は提案にとどめ、承認なしに実行しない。
7. wiki に関係する内容がない場合は、そうはっきり伝える。話をでっち上げてはならない。足りない部分を補うために取り込むとよいソースを提案する。このときは確からしさを付けず、wiki の外の知識（モデルの知識や一般的な知識）で答えを添えることもしない。添えた答えは、wiki の回答と見分けにくく、そのまま信じられたり保存されたりしやすいためである。質問の一部だけを wiki が扱っていないときも、その部分を外の知識で埋めず、扱っていないと伝える。
8. 回答が新しいつながりを見いだすものであれば、今後のクエリで役立つように `<WIKI_ROOT>/synthesis/` に保存することを提案する。提案するのを基本とし、ささいな回答ならユーザーが断れるようにする。確からしさが「低」の回答は保存を提案せず、先に上げる方法を提案する。

ユーザーが任意の判定レイヤーを有効にしている場合は、MCP のツールではなく検索スクリプト（手順 4b の `uv run --script` の形）に `--decide` を付ける。すべての行が除外された場合は、wiki にはおそらく答えがないとユーザーに伝える。詳しくは `${CLAUDE_PLUGIN_ROOT}/skills/info-hive/references/decision-models.md` を参照。
