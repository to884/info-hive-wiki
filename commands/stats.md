---
description: wiki の規模、構成、リンク密度と、スケーリングのどの閾値に達しているかを表示する。
---

`<WIKI_ROOT>` は、ユーザーが明示したパス、もっとも近いプロジェクトの指示、グローバルなエージェントの指示の順に探し、どれにもなければ作業領域の設定（`.info-hive/workspace.json`）の `dirs.wiki`、それもなければ現在のプロジェクトの `wiki/` とする。次に統計を取り、結果に簡単な解釈を添えてユーザーに示す。MCP のツールと CLI の使い分けは、`info-hive` スキルの「MCP のツールと CLI の使い分け」に従う。wiki の MCP サーバーのツール `stats` が使える場合は、`wiki=<WIKI_ROOT の絶対パス>` を渡す（ツール名は接続に表示されたもの。Claude Code では `mcp__plugin_wiki_wiki__stats`）。結果の `index` は検索の索引の状態（`state` が `ready` なら埋め込み済み、`embedding` なら裏で埋め込み中、`pending` ならまだ始めていない）、`server` はサーバーのコードの版である。索引をまだ開いていない wiki では、最初の呼び出しで wiki を読み込むので、少し時間がかかる。ツールが使えない場合は、`python "${CLAUDE_PLUGIN_ROOT}/skills/info-hive/scripts/wiki_stats.py" "<WIKI_ROOT>"` を実行する（`--json` を付けると同じ集計を JSON で返す。索引の状態は含まない）。

- wiki がスケーリングの閾値に近づいている場合は、そのことを指摘し、移行に何が必要かを説明する。閾値は、インデックスの分割が 150 ページまたはインデックス 300 行、検索スクリプトの日常的な利用が 300 ページ、週1回の lint が 500 ページである。
- ソフト上限（空白を除いて 10,000 文字か 100 行）やハード上限（25,000 文字か 200 行）を超えているページがあれば、分割を勧める。大きさは lint と同じく、コードフェンス（mermaid の図を含む）の中身と画像だけの行を除いて数える。
- リンク密度が低い（1ページあたり平均 1.5 リンク未満）場合は、相互参照が足りていない可能性がある。独立したページにすべきコンセプトを見つけるために、`--suggest-pages` を付けた lint を提案する。

移行の手順は `skills/info-hive/references/scaling-playbook.md` を参照。
